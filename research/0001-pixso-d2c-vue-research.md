# 里程碑 7 备课研究：Pixso 设计稿 → Vue3 代码（2025-09 核实）

> 用途：里程碑 7（Pixso 稿 → Vue3 代码 → 跑通 + 假数据交互）的教师备课笔记。
> 数据来源均为官方文档，动手验证留到里程碑 7（需用户实际 Pixso 文件与账号）。

## 一、官方能力现状

- **Pixso 官方 D2C / D2C⁺（设计转代码）**确实存在，支持输出 **Vue**（另有 React、HTML、ArkUI、Flutter）。
  文章：[Design to Code (D2C)](https://pixso.net/articles/design-to-code/) · 开发者文档：[D2C⁺ 快速开始（中文）](https://pre.pixso.cn/developer/zh/d2c/quick-start.html)
- 生成设置：样式提取 → `common.css`；设计 token 提取 → `design-tokens.css`；组件提取 → `component.css`；类名前缀；页面布局（响应式）；单位；命名风格（Pascal/Kebab）。
- 生成流程（官方文章）：选框架(Vue) → 配置 → 选中图层（Select frame / 框选）→ 生成代码 → 在「项目结构 / 图层列表」查看，图片资源单独浏览 → 「下载代码包」导出完整工程包。
- **D2C⁺ 开发者版**（企业研发模式）：生成「可落地前端代码」，可对接设计系统（DSM 组件映射，如 Button → el-button）。
- **Pixso MCP**（本地/远程）有 `design_to_code`、`refine_generated_code`（A 响应式 / B CSS 变量 / C Tailwind / D 精简 / E 对齐设计系统）、`get_export_image`、`take_screenshot`、`get_node_dsl` 等工具 → **AI/Agent 可直接按 Pixso 链接生成 Vue 代码**。工具文档：[工具与指令](https://pre.pixso.cn/developer/zh/mcp/tools.html)

## 二、关键约束（决定路线选择）⚠️

1. **D2C⁺ / 研发模式 / MCP 代码生成能力要求「企业版 全功能席位 或 研发席位」**；普通免费/个人版不可用。
2. **仅「企业空间」内的文件支持 D2C⁺**；个人草稿若不在企业空间也不行。
3. 文件需有可查看权限；写入类工具需编辑权限。
→ **里程碑 7 前必须向用户确认**：Pixso 账号类型 / 席位、设计文件是否在企业空间、是否愿开研发模式。若用户非企业版，官方 D2C⁺ 走不通，转路线 C。

## 三、候选路线

- **路线 A（官方 D2C⁺ 直出，最省事）**：企业版 + 企业空间 → 研发模式选 D2C⁺ → 生成 Vue 代码 → 下载代码包 → 与 Vite 工程合并（改假数据、接交互）。*待实证：下载的 Vue 代码包实际结构（是否含 .vue 单文件/是否自带构建配置）。*
- **路线 B（Pixso MCP + AI 老师代劳）**：同上席位要求；由 Agent 通过 `design_to_code` 生成，再把产物落入第 5 课搭好的 Vite 工程。适合用户不想自己在 Pixso 里点生成的情况。
- **路线 C（手工组件拆分，100% 兜底）**：无企业版时——用户选最简单一页 → 截图 + 开发模式样式/切图（图片、色值）→ 用第 6 课学的组件化思维 + AI 辅助把该页手工写成 Vue3 组件 → 假数据联通。费时但完全可控、教学价值最高。

## 四、遗留开放问题（里程碑 7 动手时核实）

- 用户 Pixso 账号：免费？个人付费？企业版？研发席位？（决定 A/B vs C）
- 设计文件是否位于企业空间（A/B 的前提）。
- Vue 代码包下载后的工程形态：是否可直接 `npm install && npm run dev`？样式如何组织？
- 图片资源导出格式与 2x 倍率如何处理。
- 中文界面上的功能入口名称（研发模式 / D2C⁺ / 开发模式）以用户实际版本为准。

## 五、对课程的影响

- 第 5 课（Vite 工程）是两条主路线的共同地基 → 顺序不变。
- 第 6 课（组件化：拆稿成组件）即使走路线 A 也值得学——D2C 出的代码仍要「读懂 + 改」，本课程目标含「能修改代码」。
- 若用户确认无企业版：把路线 C 提升为默认计划，A/B 降级为「了解即可」。
